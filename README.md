# robot-trajectory-tools

ETロボコン向けに作った，ライントレースロボットの**走行軌跡を計測・可視化するツール集**です．
天井カメラの映像から実座標を求める外部計測と，機体側オドメトリのプロット，両者の突き合わせ解析をまとめています．

オドメトリ（自己位置推定）は誤差が累積するため，それ単体では「本当に狙った経路を走れているか」が分かりません．
そこで**カメラによる外部計測を審判役**にして，オドメトリのパラメータ（車輪半径・トレッド幅）を追い込むのがこのツール群の目的です．

---

## 収録ツール

| スクリプト | 対象環境 | 入力 | 出力 | 用途 |
| --- | --- | --- | --- | --- |
| `src/軌跡ロガー_mp4版.py` | 実機 | 天井から撮影したmp4 | 軌跡CSV，軌跡画像 | 動画から赤マーカーを追跡し実座標に変換 |
| `src/pose_logger.py` | シミュレータ | 連番PNG（キャプチャ画像） | `trajectory.csv`，重畳画像 | 走行中にリアルタイムで座標を記録 |
| `src/軌跡プロット.py` | 実機 | `pybricks-data-*.csv` | 軌跡図 | 機体オドメトリのログをコース図に重ねて描画 |
| `tools/コース画像生成.py` | 共通 | コース全体図PDF | 片側コースのPNG | 背景画像の生成（下記参照） |

### 実機とシミュレータの違い

**実機**：SPIKE Prime + Pybricks で走行し，天井に固定したスマートフォン（Pixel 9a）で真上から撮影します．
機体上面の赤マーカーを追跡して外部計測とし，機体側のオドメトリログと突き合わせます．
床の材質やホワイトバランスの影響を受けるため，HSV閾値とスケールのキャリブレーションが要ります．

**シミュレータ**：athrill（V850エミュレータ）ベースの環境で，`raspike-athrill-v850e2m/sdk/workspace/capture/`
に吐かれる連番PNGを読み取ります．照明条件が一定なのでHSV閾値は固定値で足り，カメラ高さの補正も不要です．
その代わり射影変換の4点は固定値をコードに直書きしています．

## セットアップ

```bash
git clone https://github.com/ichi-choken/robot-trajectory-tools.git
cd robot-trajectory-tools
pip install -r requirements.txt
```

`tools/コース画像生成.py` のみ poppler-utils（`pdftoppm`）が別途必要です．

```bash
# Ubuntu / Debian
sudo apt install poppler-utils
```

## 背景画像（コース図）の用意

コース図はETロボコン実行委員会の配布物のため，**このリポジトリには含めていません**．
公式配布のPDF（全体図・50%縮図）を手元に置いて，次のコマンドで生成してください．

```bash
python tools/コース画像生成.py コース全体図.pdf --side L
```

生成物は `assets/Lコース全体図.png` に出力されます．

| 項目 | 値 |
| --- | --- |
| 画像サイズ | 5374 × 7166 px（DPI=100のとき） |
| 縮尺 | 19.6868 px/cm |
| 実寸 | 273.0 cm × 364.0 cm |

実測値は272.7cm × 364.2cmで，PDF由来の値と3mm以内で一致することを確認済みです．
`--side R` でRコース，`--dpi` で解像度を変更できます．

## 座標系

計測系ごとに原点と軸の向きが違うため，突き合わせの前に必ず変換が要ります．
詳細は [`docs/座標系とキャリブレーション.md`](docs/座標系とキャリブレーション.md) を参照してください．

- **カメラ計測**：右上を原点とし，x軸は右上→左上方向，z軸は右上→右下方向
- **オドメトリ**：初期進行方向を0°とし，反時計回りが正．プロット時は `plot_x = -odo_x`，`theta = 90° + o_deg`
- 単位はカメラ側がmm，オドメトリ側がcm

---

## 計測時の注意点

- **カメラ高さの補正**：マーカーは床から浮いているため，そのままだと見かけの移動量が実寸より大きく出ます．カメラ高さ `H` とマーカー高さ `h` から `(H - h) / H` を掛けて補正します
- **赤マーカーのHue**：赤はHueが0°をまたぐため，`0〜10` と `165〜180` の両端を併用します．スマートフォンのホワイトバランスによって同じ赤紙でも明るい場所と暗い場所でHueが大きく振れるためです
- **自己検証**：既知のマーカー径（42.5mm）を毎回検出値と比較すると，キャリブレーション全体が壊れていないかを1行で確認できます
