# robot-trajectory-tools

ETロボコン向けに作った，ライントレースロボットの**走行軌跡を計測・可視化するツール集**です．
天井カメラの映像から実座標を求める外部計測と，機体側オドメトリのプロット，両者の突き合わせをまとめています．

オドメトリ（自己位置推定）は誤差が累積するため，それ単体では「本当に狙った経路を走れているか」が分かりません．
そこで**カメラによる外部計測を審判役**にして，オドメトリのパラメータ（車輪半径・トレッド幅）を追い込むのが目的です．

---

## 収録ツール

| スクリプト | 対象環境 | 入力 | 出力 | 用途 |
| --- | --- | --- | --- | --- |
| `src/camera_trajectory_logger.py` | 実機 | 天井から撮影したmp4 | `軌跡.csv`，軌跡画像 | 動画から赤マーカーを追跡し実座標に変換 |
| `src/pose_logger.py` | シミュレータ | 連番PNG（キャプチャ画像） | `trajectory.csv`，重畳画像 | 走行中にリアルタイムで座標を記録 |
| `src/odometry_plot.py` | 実機 | `pybricks-data-*.csv` | `plot.png` | 機体オドメトリのログをコース図に重ねて描画 |
| `tools/generate_course_image.py` | 共通 | コース全体図PDF | 片側コースのPNG | 背景画像の生成 |

### 実機とシミュレータの違い

**実機**：SPIKE Prime + Pybricks で走行し，天井に固定したスマートフォン（Pixel 9a）で真上から撮影します．
機体上面の赤マーカーを追跡して外部計測とし，機体側のオドメトリログと突き合わせます．
床の材質やホワイトバランスの影響を受けるため，HSV閾値とスケールのキャリブレーションが要ります．

**シミュレータ**：athrill（V850エミュレータ）ベースの環境で，`capture/` に吐かれる連番PNGを読み取ります．
照明条件が一定なのでHSV閾値は固定値で足り，カメラ高さの補正も不要です．
その代わり射影変換の4点は固定値をコードに直書きしています．

## 使い方 A：動画から軌跡を出す（実機）

### 撮影の準備

1. スマートフォンを天井に固定し，コースを**真上から**撮影する（斜めだと射影歪みが乗ります）
2. 機体上面に**赤い円マーカー**（直径42.5mm）を貼る
3. 床の写る位置に**一辺150mmのティール色の正方形**（参照マーカー，折り紙など）を置く．これで `mm/px` を自動算出するため必須です
4. カメラ高さ（床からレンズまで）とマーカー高さ（床からマーカー紙面まで）をメジャーで測っておく

### ファイルの置き場所

スクリプトは**実行時のカレントフォルダ**から入力を探します．
`src/` に移動してから実行する前提なので，撮影した動画は `src/` 直下に置いてください．

```
robot-trajectory-tools/
└─ src/
   ├─ camera_trajectory_logger.py
   ├─ 走行20260903.mp4      ← ここに置く（ファイル名は任意）
   └─ 背景グリッド.png       ← 任意．無ければ自動生成される
```

`*.mp4` は `.gitignore` で除外済みなので，ここに置いてもコミットされません．

背景は，同じフォルダに `背景グリッド.png` があればそれを使い，無ければ実行時にフレームサイズに合わせて自動生成します．
**通常は用意しなくて構いません．**

### 実行

**カレントフォルダの `*.mp4` から更新日時が最新のものを自動選択**します．ファイル名の指定は要りません．

```bash
cd src
python camera_trajectory_logger.py
```

複数の動画を置いている場合は，解析したいものを最後にコピーし直すか，他を別フォルダへ退避してください．

処理中はCtrl-Cで中断できます．中断してもそこまでの結果は保存されます．

### 出力

| ファイル | 内容 |
| --- | --- |
| `軌跡.csv` | フレームごとの時刻[ms]，画像座標，実座標[mm] |
| `軌跡画像.jpg` | グリッド背景に軌跡を重ねた図．60フレーム（約2秒）ごとに更新 |
| `マスク確認.jpg` | 赤マーカーの検出マスク．**まずこれを見ること** |

タイムスタンプは実時間ではなく「フレーム番号 ÷ fps」による動画内時間です．

### 実行前に合わせるパラメータ

スクリプト冒頭にまとまっています．

```python
CAM_HEIGHT_MM = 1990.0     # カメラ高さ（床からレンズまで）[mm]
MARKER_HEIGHT_MM = 161.0   # マーカー高さ（床から赤マーカー紙面まで）[mm]
MARKER_DIAMETER_MM = 42.5  # 赤マーカーの実径[mm]
REF_SQUARE_MM = 150.0      # 参照マーカーの一辺[mm]
MAX_JUMP_PX = 80           # 1フレームあたりの許容移動量[px]
PROCESS_EVERY = 1          # 処理が重いときは 2〜3 に上げてフレームを間引く
```

`CAM_HEIGHT_MM` と `MARKER_HEIGHT_MM` は `(CAM_HEIGHT_MM - MARKER_HEIGHT_MM) / CAM_HEIGHT_MM` の補正に使います．マーカーは床から浮いているので，これを掛けないと移動量が実寸より大きく出ます．

### うまくいかないとき

**マーカーが検出されない**
`マスク確認.jpg` を開き，赤マーカーだけが白く抜けているか見てください．
抜けが悪ければ `RED_RANGES` のS・V下限を下げます（屋内照明では彩度が落ちるため，Sの下限を70〜80程度まで）．

**赤以外を拾っている**
低Hue側（`0〜10`）が濃い木目や壁際を誤検出することがあります．撮影環境が安定しているなら，このレンジを外す判断もあります．

**軌跡が飛ぶ**
`MAX_JUMP_PX` を小さくします．逆に速く走らせて追従が切れる場合は大きくします．

**画像が更新されない**
`軌跡画像.jpg` を画像ビューアで開いたままだとファイルがロックされ，上書きに失敗します．
その場合は `軌跡画像_143052.jpg` のように時刻付きの別名で保存されるので，ビューアを閉じて再実行してください．

**検出径が実径と合わない**
実行時にマーカーの検出径と実径（42.5mm）の比較が表示されます．ここが大きくずれていたら，
参照マーカーの検出かカメラ高さの入力を疑ってください．キャリブレーション全体の健全性チェックになります．

## 使い方 B：連番PNGから軌跡を記録（シミュレータ）

走行と**並行して**動かします．キャプチャフォルダを監視し，新しいPNGが増えるたびに座標を追記します．

```bash
# ターミナル1: シミュレータで走行を開始
# ターミナル2:
python src/pose_logger.py
```

起動時に既存のPNGを削除してから監視を始めます（前回の走行分を拾わないため）．
終了はCtrl-Cです．

### 出力

| ファイル | 内容 |
| --- | --- |
| `workspace/trajectory.csv` | `timestamp`（ms），`x`，`z` |
| `workspace/result/` | 軌跡を重ねた画像 |

### パラメータ

射影変換の4点は固定値です．キャプチャの画角を変えたら書き換えてください．

```python
CAPTURE_DIR = "./raspike-athrill-v850e2m/sdk/workspace/capture/"
src = ...   # 画像座標の4点（右下 → 左下 → 左上 → 右上）
dst = ...   # 対応する実座標[mm]
```

背景画像も固定パスから読み込みます．コース図を使う場合は「使い方 D」で生成したものを，
スクリプトが参照しているパスにコピーしてください．最新フレームを背景にしたい場合は，その読み込み行を
`cv2.imread` から差し替えます．

## 使い方 C：オドメトリのログをプロット（実機）

Pybricksが出力した `pybricks-data-*.csv` を読み，コース図に重ねて描画します．
**指定フォルダ内で更新日時が最新のCSV**を自動選択します．

```bash
python src/odometry_plot.py
```

### ファイルの置き場所

背景画像とログCSVを次のように配置します．

```
robot-trajectory-tools/
├─ assets/
│  └─ Lコース全体図.png          ← 「使い方 D」で生成される
└─ src/
   ├─ odometry_plot.py
   ├─ background.png             ← 上をこの名前でコピーする
   └─ pybricks-data-20260903.csv ← ログCSV（ファイル名は任意）
```

スクリプトは背景を `background.png` という名前で読むため，**生成した画像をコピーして名前を変える**必要があります．

```bash
cp assets/Lコース全体図.png src/background.png          # Linux / macOS
copy assets\Lコース全体図.png src\background.png        # Windows
```

ログCSVは `CSV_DIR`（既定はカレントフォルダ）にある `pybricks-data-*.csv` のうち，
**更新日時が最新のもの**が自動で選ばれます．過去の走行分を残しておくと誤って拾うので，別フォルダに退避してください．

CSVは UTF-8 BOM付き，単位はcmで，`odo_x`，`odo_y`，`o_deg` の列が必要です．

描画結果はカレントフォルダに `plot.png` として保存されます．

### 調整用パラメータ

スクリプト冒頭に集約してあります．

```python
CSV_DIR = "."               # CSVを探すフォルダ
VEHICLE_WIDTH_CM = 12.5     # 車体幅（軌跡に帯として描く．0で無効）
ARROW_STEP_CM = 10.0        # 方位矢印の間隔（走行距離ごと）
ARROW_LEN_CM = 8.0          # 方位矢印の長さ
X_SIGN = -1.0               # odo_x の符号（写真の向きに合わせる）
THETA_OFFSET_DEG = 90.0     # 方位角のオフセット
ODO_UNIT = "cm"
```

### 軌跡がコース線からずれるとき

原因は影響の大きい順に3つです．

1. **オドメトリの累積誤差**（車輪半径・トレッド幅の較正不足）
2. **ライン中心からのオフセット**（エッジ追従なので構造的にずれる）
3. **原点位置の仮定**（スタートライン手前10cmとしている前提が実際と合っているか）

較正の詳細は [`docs/座標系とキャリブレーション.md`](docs/座標系とキャリブレーション.md) を参照してください．

## 使い方 D：コース背景画像の生成

コース図はETロボコン実行委員会の配布物のため，**このリポジトリには含めていません**．
公式配布のPDF（全体図・50%縮図）を手元に置いて生成してください．

```bash
python tools/generate_course_image.py コース全体図.pdf --side L
```

| オプション | 既定値 | 内容 |
| --- | --- | --- |
| `--side` | `L` | 切り出す側（`L` / `R`） |
| `--dpi` | `100` | ラスタライズ解像度 |
| `--out` | `assets/{side}コース全体図.png` | 出力先 |

生成物の仕様（DPI=100のとき）：

| 項目 | 値 |
| --- | --- |
| 画像サイズ | 5374 × 7166 px |
| 縮尺 | 19.6868 px/cm |
| 実寸 | 273.0 cm × 364.0 cm |

実測値は272.7cm × 364.2cmで，PDF由来の値と3mm以内で一致することを確認済みです．

### 生成後にやること

`odometry_plot.py` は `background.png` という名前で背景を読むため，コピーして名前を合わせます．

```bash
cp assets/Lコース全体図.png src/background.png          # Linux / macOS
copy assets\Lコース全体図.png src\background.png        # Windows
```

> このコピー作業は暫定です．スクリプト側の参照先を `assets/` に直せば不要になります．

## 座標系

計測系ごとに原点と軸の向きが違うため，突き合わせの前に必ず変換が要ります．

- **カメラ計測**：右上を原点とし，x軸は右上→左上方向，z軸は右上→右下方向．単位はmm
- **オドメトリ**：初期進行方向を0°とし，反時計回りが正．単位はcm
- プロット時は `plot_x = -odo_x`，`theta = 90° + o_deg`

画像座標は左手系なので，オドメトリ（右手系）と比較するときはyを反転してから揃えます．

詳細は [`docs/座標系とキャリブレーション.md`](docs/座標系とキャリブレーション.md) にまとめています．
